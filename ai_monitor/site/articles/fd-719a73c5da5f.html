Vercel Daemons 新增 OTel 追蹤

Node.js daemon 使用預設設定並升級 @vercel/otel 後，可經 Unix socket 自動將 OpenTelemetry 追蹤資料送到 Vercel Tracing，讓開發者與 AI 代理程式一併檢視背景工作。

英文搜尋標題:Vercel Daemons Add OpenTelemetry Tracing

內文

Vercel Daemons 是 Vercel 平台用來執行背景工作的程序。這次更新加入將 OpenTelemetry 追蹤資料送往 Vercel Tracing 的能力，開發者與 AI 代理程式可將背景 worker 記錄的運作情況，連同專案其他部分的追蹤資料放在同一環境檢視，不必再把背景紀錄與其他追蹤分開處理。

Vercel 會為每個 daemon 提供一個用來接收 OTLP/HTTP 追蹤資料的 Unix socket，並把路徑寫入 VERCEL_OTEL_SOCKET_PATH。將 @vercel/otel 升級至 2.3.0 或以上後，使用預設設定的 Node.js daemon 會自動匯出追蹤；SDK 會識別 socket，將 worker 記錄的追蹤片段（spans）傳送到 Vercel。Vercel Tracing 亦可按服務名稱搜尋專案內的追蹤，並向代理程式回傳 JSON。

過去要弄清背景 worker 做過甚麼，往往要翻查分散日誌，或自行接駁追蹤工具；現在可在 Vercel Tracing 對照背景工作與專案其餘追蹤。這適合運行 Node.js daemon，又希望由工程人員或 AI 代理程式檢查 worker 行為的團隊；團隊可用服務名稱定位資料，代理程式則可取得 JSON 結果。

同類選擇包括 OpenTelemetry Collector 及其他分散式追蹤平台；不過材料未確認它們能否直接使用 Vercel 提供的 socket。安裝或升級前應檢查現有 @vercel/otel 版本、部署設定與環境限制，亦要留意 Unix socket、OTLP/HTTP 傳輸方式，以及 Node.js 預設自動匯出條件。

點解要理

  • Vercel 為每個 daemon 提供 OTLP/HTTP 追蹤用的 Unix socket，路徑設於 VERCEL_OTEL_SOCKET_PATH。
  • @vercel/otel 升級至 2.3.0 或以上後，採用預設設定的 Node.js daemon 可自動匯出追蹤。
  • Vercel Tracing 可按服務名稱搜尋專案內追蹤，並可向代理程式回傳 JSON。
